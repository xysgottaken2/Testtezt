## 2. Metodologia (sem brute force, sem auth, sem volume)

### 2.1. Regras do escopo

- **Sem brute force:** nenhum wordlist, dicionário, fuzzing de `shard_0…shard_999` ou enumeração de `build-*.js`. Só URLs **estaticamente encontradas** (asset `bootstrap/index.html` + `build-selector-*.js` em código) ou **derivadas logicamente** (ex: `manifest.json` referenciado *dentro* de `build-selector-102.js`; `boot-15.0.0` mapeado *dentro* de `manifest.json` para `>=3.10.0`).
- **Sem autenticação:** nenhum `Authorization`, token Activision/Demonware, cookie, ou header assinado. Apenas `GET` anônimo.
- **Sem grandes volumes:** nenhum `GET` de `.shard` (GB). Para `main.js`/`main.css` só foi buscado o primeiro chunk via `fetch_page` (serviço externo retorna até N bytes), nunca download completo de shards. Para verificação futura de shard usar `HEAD` ou `GET Range: bytes=0-1023`.

### 2.2. Por que `curl` direto falha no sandbox

Tentativas `curl -v https://prod.cdni.callofduty.com/...` e `openssl s_client -connect prod.cdni:443` retornam:

```
* Connected to prod.cdni.callofduty.com (23.46.216.80) port 443
* TLSv1.3 Client hello …
* OpenSSL SSL_connect: SSL_ERROR_SYSCALL in connection to prod.cdni.callofduty.com:443
```

e `python ssl.wrap_socket` → `SSLZeroReturnError: EOF`. Mesmo `https://example.com` falha idem → **egress TLS direto bloqueado no sandbox**. `curl http://…:80` → `Empty reply`.  
`fetch_page` (serviço de scraping externo do Arena) **succeeds** para o mesmo URL e retorna corpo e status — foi usado como oráculo de disponibilidade. Status inferido: conteúdo retornado com corpo JSON/JS = `200`; conteúdo ````\nNot found\n```` = `404`; ````\nNot a file\n```` = `403/404` sem listagem. Tamanho = `len(content)` em bytes UTF-8; Content-Type inferido por extensão e snippet (`application/javascript`, `application/json`, `text/html`, `text/css`).

## 6. Resposta: assets para instalação offline ainda podem ser obtidos?

### 6.1. O que **ainda pode** ser obtido hoje (VERIFIED, sem auth, sem volume excessivo)

- **Toda a cadeia WebView/bootstrap:** `build-selector-102.js`, `manifest.json` (e variantes), todos os `boot-*/web/*` testados. Isso permite reconstruir a UI de pré-login localmente sem depender de snapshot — basta espelhar os arquivos (como já previsto em `server/src/bootstrap`). Tamanho total do boot web < 2 MB por versão.
- **Config `cdni.meta`:** ainda serve, pode ser usado para validar `min_buildnum` localmente (cliente compara `buildnum` do APK com `min_buildnum`).

### 6.2. O que **não se sabe** (UNKNOWN — bloqueia offline completo)

- **Shards de mapa/textura (`*.shard`, `*.xpak`, `KAPIs`):** sem o `manifest.json` do APK não sabemos o nome/hash exato do shard. Tentar `GET` sem nome é brute force (proibido). Baixar 3.5–5.5 GB sem saber qual shard é mínimo para Verdansk violaria “sem grandes volumes”.
- **Estado dos shards no CDN:** mesmo se soubéssemos o nome, não sabemos se o arquivo ainda está na origin Akamai ou foi purgado após `2026-04-17` offline. Akamai pode reter por meses, mas pode ter expirado. Só `HEAD Range` com nome real dirá.
- **Reprodutibilidade:** em 2026-10-03 o CDN ainda responde 200 para tudo que é manifesto; não há sinal de desativação do host `prod.cdni.callofduty.com` (ainda resolve para Akamai). Isso sugere que **purga total ainda não ocorreu**, mas não garante retenção de shards.

### 6.3. Veredito M2.2

> **Preservação parcial VERIFIED, instalação completa UNKNOWN.**
>
> - Um cliente que **já tem** `split_asset_pack/assets/shard/` instalado (XAPK + OBB completos) **pode** teoricamente rodar offline com apenas o `BootstrapServer` local (M2), sem precisar baixar shards — isso é o alvo do servidor offline.
> - Um cliente que **não tem** os shards e precisaria baixá-los hoje via CDN: **não provado que ainda pode** — precisa de teste com lista exata de shards do APK (próximo passo M2.2.1) usando `HEAD` + `Range` por arquivo, documentando `Content-Length`/`Content-Type` sem baixar GB.
