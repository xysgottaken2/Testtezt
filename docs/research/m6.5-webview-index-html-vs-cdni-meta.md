## 0. Veredito

**Esses fluxos são independentes: fazer `/static/web/index.html` devolver o JSON do `cdni.meta` não teria efeito.** A única ponte real entre "a página" e o fluxo de inicialização é um **canal de comandos** (nome → handler) e não o corpo da resposta — logo, o que a página *contém* só importa na medida em que o JavaScript dela *executa comandos da bridge*.

Prova negativa central: as cadeias **`/static/` = 0 ocorrências** e **`build-selector` = 0 ocorrências** no arquivo inteiro (91 196 224 B). `VERIFIED`. Não existe nenhum consumidor nativo desse path, portanto nenhuma forma de "enganá-lo" com o corpo do meta.

## 4. Por que o corpo do meta nesse path não chegaria ao `MetaFetchTask`

1. `MetaFetchTask` busca a URL que **ele mesmo** obtém de `nativeGetCDNiMetaUrl()` — literal fixa `…/wzm/shard_cdn/android/_manifest/cdni.meta` (`0x4e45b8`), um único xref. Ela não é derivada da página, nem do `webviewdata`, nem de `region_detection_option`. `VERIFIED` + `USER_SUPPLIED` (você no DEX).
2. A resposta do meta é parseada como JSON **nessa** chamada (`HttpURLConnection` → HTTP 200 → `new JSONObject(str)`, `USER_SUPPLIED`) e entregue ao nativo (`0x159bf88`). Não existe um caminho "documento do WebView → JSONObject".
3. `/static/web/index.html` é **navegação de documento** dentro do WebView (o `build-selector-103.js` faz `location.href`). Um corpo JSON ali seria renderizado como texto. Nada o parseia. `VERIFIED` (1) + `PROBABLE` (2–3, por ser o comportamento padrão do WebView).
4. No lado do launcher, o corpo real do meta **já** é servido onde importa: `BootstrapEndpoints.kt` → `path = CdnRouterConfig.CDNI_META_PATH` (`/wzm/shard_cdn/android/_manifest/cdni.meta`) com `realUpstreamBody = true` e `body = { CdniMetaBody.android() }`. Servir o mesmo corpo no path HTML é, além de inócuo, **redundante**. `VERIFIED` (código lido agora).

## 5. Sobre "sumiu a tela de shutdown quando o endpoint passou sem interceptação"

Fato de configuração `VERIFIED`: `CdnRouterConfig.INTERCEPT_HOSTS = listOf("prod.cdni.callofduty.com")` — o **mesmo host** responde por `/static/web/index.html` e por `/wzm/shard_cdn/android/_manifest/cdni.meta`; a tabela de rotas casa por path (`CdnRouteTableTest.kt:44-45` exercita exatamente `GET https://prod.cdni.callofduty.com/static/web/index.html`). Então o seletor é *path*, e o que você observou é uma mudança **de conteúdo renderizado**, não de decisão de update.

O que a observação **não** prova: que a página participa da escolha de fluxo. Ela só prova que a tela é texto vindo daquele documento. `HYPOTHESIS` (e a única versão que a evidência atual sustenta) : a tela de "fora de serviço" é um efeito colateral visual do documento servido; o que decide o fluxo é (a) o `MetaFetchTask`/CDNI e (b) o **fence** (`passPreloginFence` → `0x11d1730` → `dlog_event_webview_closed`).

## 6. O que a hipótese tinha de realmente interessante (e não é o JSON)

Existe um caminho tecnicamente possível de *página → inicialização*, mas ele passa por **executar comandos**, não por devolver JSON:

* `passPreloginFence` (thunk `0x11dc460`) é o comando que libera o cercado de pré-login e fecha o WebView (`0x11d1730`).
* `CDNI_UseDevServer` (`0x11dd024` → `0x159f524("use_dev_cdn")`) mexe na mesma família de estado que o `0x15af1d4` usa para escrever o byte em `0x6c15d90` e chamar `slot 0x58` do objeto `0x6c142d0` — o setter da base do CDN (ver [m6.4 §2](m6.4-cadeia-cdni-libcurl-dump.md)).

Dois bloqueios `UNKNOWN` que precisam ser resolvidos **antes** de sonhar com isso, e que não se resolvem no binário:

1. **Timing:** a tabela de comandos é registrada pela engine (`0x11cdaec` ← `0x11cd6cc`). O `bootstrap/index.html` é carregado por `MainActivity.loadWeb` na fase **pré-engine** (`USER_SUPPLIED`/m4.7). Se a bridge ainda não existe quando a página roda, ela não tem o que chamar. `UNKNOWN`.
2. **Superfície exposta:** quais desses nomes o WebView do bootstrap realmente expõe ao JS depende do DEX (`addJavascriptInterface`/`@JavascriptInterface`/`WBootstrap`/`MainActivity.loadWeb`). No `.so` há **0** ocorrências de `JavascriptInterface`/`android/webkit`, então a resposta está só no DEX. `UNKNOWN` aqui, verificável por você com o scanner.
