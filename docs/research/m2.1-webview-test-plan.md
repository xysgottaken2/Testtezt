## 2. Por que `hosts` não é menos invasivo

`hosts` patch (`127.0.0.1 prod.cdni...` em `/etc/hosts` ou `/system/etc/hosts`) exige:

- `adb root` + `adb remount` ou `magisk` — **S23 Ultra sem root = impossível**
- Escrita em partição system — Knox trip, reboot, e risco de brick

Portanto desclassificado para S23 stock.

## 3. Detalhamento do recomendado A — Hotspot DNS

### 3.1. Arquitetura

```
[S23 Ultra]
   | Wi-Fi (conecta em "WZM-Offline-Test" hotspot do PC)
   | DNS: 192.168.12.1 (PC)
   v
[PC Linux] hotspot (NetworkManager / create_ap)
   ├─ dnsmasq: --address=/prod.cdni.callofduty.com/192.168.12.1
   └─ BootstrapServer: 0.0.0.0:18081  (serve build-selector-103.js + offline page)
             ↑
WebView GET https://prod.cdni.callofduty.com/manifest/build-selector-103.js
  → DNS retorna 192.168.12.1 (PC) → TLS SNI=prod.cdni... → BootstrapServer (plain HTTP aqui)
```

**Limitação TLS:** `https://prod.cdni...:443` com SNI `prod.cdni...` mas cert é de `BootstrapServer` self-signed.  WebView pode rejeitar (`ERR_CERT_AUTHORITY_INVALID` / pinning).  **Solução M2.1 sem pinning bypass:** BootstrapServer escuta como **HTTP** em `:18081` e dnsmasq aponta `prod.cdni` para PC, mas WebView tenta `https://...:443` → precisará de TLS cert válido para `prod.cdni...` ou HTTP downgrade.

Para teste inicial **sem pinning**, usamos **HTTP downgrade via proxy transparente**: hotspot faz `iptables -t nat ... 443 -> 18081` e BootstrapServer fala TLS com cert gerado para `prod.cdni`?  Alternativa mais simples M2.1: testar primeiro se WebView aceita `http://` se asset fosse `http://` — mas asset é `https://`.  Então hotspot DNS **sozinho não basta** sem TLS; por isso B é fallback.

**Decisão prática M2.1:** tentar **A sem TLS** primeiro e **documentar onde falha** (`ERR_CERT` em `adb logcat | grep -i cert`) — isso já é resultado VERIFIED (prova de pinning/cert).  Então cair para **B com mitmproxy** que gera cert dinâmica e pode ser instalado como CA user em S23 (sem root, apenas instalar cert em `Configurações > Segurança > Credenciais`).

### 3.2. Passos reproduzíveis no S23 Ultra (sem root)

#### No PC (Linux) — preparação (10 min)

```bash
# 1. Instalar deps (uma vez)
sudo apt update && sudo apt install -y dnsmasq iptables

# 2. Criar hotspot (NetworkManager)
nmcli device wifi hotspot ifname wlan0 con-name WZM-Offline-Test ssid WZM-Offline-Test band bg password wzmoffline123

# 3. Ver IP do hotspot (ex.: 10.42.0.1)
ip -4 addr show nm-bridge | grep inet

# 4. Iniciar dnsmasq que resolve prod.cdni para PC
sudo dnsmasq --no-daemon \
  --listen-address=10.42.0.1 \
  --address=/prod.cdni.callofduty.com/10.42.0.1 \
  --port=53 &

# 5. NAT 443 -> BootstrapServer (se testar HTTPS)
sudo iptables -t nat -A PREROUTING -p tcp --dport 443 -j REDIRECT --to-port 18081

# 6. Iniciar BootstrapServer (já testado localmente)
cd /home/user/Testtezt/warzone-offline/server
npm ci
npm run dev:bootstrap -- --host 0.0.0.0 --port 18081
# ou: node src/bootstrap/index.js (ver warzone-offline/tools/webview-test/run-bootstrap.sh)
# Testar: curl -k https://prod.cdni.callofduty.com/manifest/build-selector-103.js --resolve prod.cdni.callofduty.com:443:10.42.0.1
```

#### No S23 Ultra — One UI (sem root)

1. **Ajustes → Conexões → Wi-Fi** → conectar em `WZM-Offline-Test` (senha `wzmoffline123`)
2. **Manter Wi-Fi ligado** (desligar dados móveis para forçar DNS do hotspot)
3. **Habilitar Depuração USB:** Ajustes → Sobre o telefone → Informações do software → tocar 7x em `Número da compilação` → Ajustes → Opções do desenvolvedor → ativar `Depuração USB`
4. **Conectar via adb (sem root):**
   ```bash
   adb devices  # deve listar S23
   adb logcat -c
   adb logcat | grep -i -E "WebView|WBootstrap|Meta Fetch|cdni|cert" | tee /tmp/wzm/m2.1-logcat.txt &
   ```
5. **Abrir WZM 3.10.0** (instalação play-store existente, não reinstalar)
6. **Observar:** WebView bootstrap deve tentar GET `prod.cdni...` → hotspot DNS retorna `10.42.0.1` → request chega em `BootstrapServer/__hits`
7. **Verificar no PC:**
   ```bash
   curl http://10.42.0.1:18081/__hits | jq
   # deve conter: {"path":"/manifest/build-selector-103.js","host":"prod.cdni.callofduty.com"}
   ```

#### Resultado esperado (regra 12/13)

- **Se capturar** `host === prod.cdni.callofduty.com` em `__hits`: `VERIFIED — observado em execução` que S23 respeita hotspot DNS → M2.1 **passa** sem APK patch.
- **Se falhar com `ERR_CERT_AUTHORITY_INVALID` ou `connection refused` em logcat:** documentar `onde falhou` (TLS), `evidência` (logcat line), `provável causa` (cert pinning / HSTS), `próximo experimento` → cair para **B (proxy + CA)**.
- **Se WebView ignora hotspot DNS (usa DNS over TLS 8.8.8.8):** fallback para **B** (proxy manual no Wi-Fi avançado).

### 3.3. Reversibilidade (sem deixar rastro)

- No S23: esquecer Wi-Fi `WZM-Offline-Test`
- No PC: `sudo iptables -t nat -D ...` ; `killall dnsmasq` ; `nmcli connection down WZM-Offline-Test`
- Sem alteração persistente no S23, sem Knox trip.

## 4. Fallback B — Wi-Fi manual proxy + mitmproxy (se A falhar por TLS)

### 4.1. Ideia

S23 → Proxy `10.42.0.1:8080` (mitmproxy) → mitmproxy script repassa `prod.cdni` para `BootstrapServer:18081`, outros hosts passam direto (sem tocar Activision).

### 4.2. Passos S23 (sem root, mas instala CA)

1. S23 Wi-Fi `WZM-Offline-Test` → **Avançado → Proxy → Manual → Host 10.42.0.1 Porta 8080**
2. PC: `mitmproxy --mode regular --listen-port 8080 --scripts warzone-offline/tools/webview-test/mitm-redirect.py`
   - Script: se `request.host == "prod.cdni.callofduty.com"` → return `BootstrapServer` response, senão `pass`
3. Instalar CA mitmproxy no S23: `curl http://mitm.it` no Chrome do S23 → baixar `mitmproxy-ca-cert.cer` → Instalar em `Cofre de credenciais` (sem root, user CA)
4. **Risco:** WebView pode usar **pinning** (ver `lib-inspect.sh` procurou `TrustManager`) — se `pinning` VERIFIED, WebView rejeita CA user → documentar `Pinning VERIFIED` e então só APK patch resolve (D, ver §5).

### 4.3. Por que B é mais invasivo que A

- Requer instalar CA (um toque extra, mas reversível)
- Requer mitmproxy (mais software)
- Ainda sem root, sem APK
