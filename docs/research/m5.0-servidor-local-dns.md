## 8. Execução no próprio celular (sem root) — decisão de 2026-10-05

O usuário definiu: **tudo dentro do launcher, no próprio aparelho, sem root e sem APK modificado**. Portas altas são aceitas. A VPN/TUN é **somente transporte** — nunca o backend.

### 8.1 O que o launcher já tem (reaproveitado, sem reescrever)

| Peça existente | Papel |
|---|---|
| `BootstrapEndpoints` + `CdnRouterConfig.CDNI_META_PATH` | rota **VERIFIED** de `/wzm/shard_cdn/android/_manifest/cdni.meta` |
| `CdniMetaBody` | corpo **real** do meta (`min_buildnum=19854920`) |
| `CdnRouteTable.respond()` | 200 para endpoint conhecido; **404 controlado e registrado** para desconhecido (= captura da próxima etapa) |
| `RequestLog` / `TunDiagnostics` | contadores `dnsQueries`, `dnsIntercepted`, `tlsOk`, `tlsFailed`, `httpRequests`, `unknownRequests`, TUN por versão/protocolo |
| `LocalHttpsServer` + `TlsContextFactory` | listener HTTPS no endereço do túnel |
| `DnsResponder` | responde `A = 10.111.222.1` para o host exato e 1 nível de `cdni.callofduty.com` |

O servidor local do Python (`warzone-offline/local-server/`) permanece como **referência e caminho alternativo em PC**; no aparelho quem responde é o launcher.

### 8.2 O gargalo real: a consulta não chega ao nosso DNS

O logcat mostra `DNS Requested by 8952, 10692(…warzone), 7(NODATA)` e **nenhuma consulta no nosso TUN**, mesmo com Private DNS em `Automatic`. A pergunta decisiva é: **o netId 8952 é a nossa VPN?** Para responder sem root:

* novo `NetworkPathReport` (M5.0) imprime, ao estabelecer o túnel, o **netId de cada rede**, seus transportes, qual é a default e o DNS de cada uma, além do estado do **Always-on VPN** (`Settings.Secure`: `always_on_vpn_app`, `always_on_vpn_lockdown`);
* compare o `netId da nossa VPN = X` do log do launcher com o `DNS Requested by <netId>` do logcat: **se forem diferentes, o WZM está resolvendo fora da VPN** e nenhum ajuste de DNS/servidor adianta.

### 8.3 Se o WZM estiver fora da VPN — o que fazer (sem root, sem mexer no APK)

1. **VPN sempre ativa** para o launcher: Ajustes → Conexões → VPN → engrenagem → **Sempre ativa** e **Bloquear conexões sem VPN**. É configuração do aparelho, não altera o app do jogo. Isso é justamente o que impede um app de usar uma rede própria fora do túnel.
2. **Private DNS → Desligado** (com DoT o sistema desvia da porta 53 do túnel).
3. Repita o teste e compare os netIds novamente.

Se, mesmo assim, o netId da consulta não for o da nossa VPN, registramos o resultado e a conclusão passa a ser: **sem root, no Android, não há outro mecanismo para redirecionar o DNS de um app de terceiro** — aí a decisão (root/Magisk ou não) é do usuário.

### 8.4 Depois que a consulta chegar

1. `dnsIntercepted` > 0 e o log mostra `prod.cdni.callofduty.com` → `A 10.111.222.1`;
2. TCP para `10.111.222.1:443` → o listener atende; `tlsOk`/`tlsFailed` separam os estágios;
3. **handshake falha** (esperado) → blocker de confiança, documentado e tratado à parte;
4. com confiança resolvida → `http_request` 200 no `cdni.meta` → o próximo **404 registrado** revela a próxima etapa.
