## 5. O que precisamos do seu lado (DEX) — **ação necessária**

O workspace **não** tem o APK nem o DEX (e o APK não deve ir para o GitHub). Rode localmente, na pasta já extraída do APK 3.10.0:

```bash
# (o scanner está neste repositório; use o caminho do seu clone)
python3 warzone-offline/tools/apk-analysis/dex-scan.py --dex classes*.dex \
    --search MetaFetchTask cdni.meta pre-login.json build-selector environment.config \
             cdni_manifest "prod.cdni.callofduty.com" \
    --json /tmp/wzm/dex-hits.json | head -200

python3 warzone-offline/tools/apk-analysis/dex-scan.py --dex classes*.dex \
    --list-classes --class-filter "preenginetasks|preengine|bootstrap|WBootstrap" | head -100

python3 warzone-offline/tools/apk-analysis/dex-scan.py --dex classes*.dex \
    --dump-strings "preenginetasks|MetaFetch" --max-per-method 40 | head -300
```

Se preferir enviar arquivos, **só** estes (nada de APK inteiro):

```
AndroidManifest.xml
res/xml/network_security_config.xml      # se existir (define se o app aceitaria CA de usuário)
classes.dex  classes2.dex  classes3.dex  classes4.dex …   # os que existirem
assets/bootstrap/index.html              # se existir (bootstrap da WebView)
```

Validação: `python3 warzone-offline/tools/apk-analysis/dex-scan.py --self-test` e, opcionalmente, `--apk seu.apk` (lê os dex do zip sem extrair).

**Por que `AndroidManifest.xml` e `network_security_config.xml` importam:** é o que decide se o aparelho pode confiar numa CA de usuário (`<base-config>` / `<debug-overrides>` / `cleartextTrafficPermitted`). Isso responde, sem tentar nada, se o estágio 3 (handshake) tem solução sem root. `UNKNOWN` até lá.

## 6. Estágios do primeiro teste real (e o blocker esperado)

1. **DNS** — `logs/dns.jsonl`: `"result": "autoritativo_a"`, `"name": "prod.cdni.callofduty.com"`.
2. **TCP + SNI** — `logs/requests.jsonl`: `tls_client_hello` com `sni=prod.cdni.callofduty.com`.
3. **Handshake** — esperado `tls_handshake_failed` enquanto o cliente não confiar no nosso certificado.
4. **Request** — `http_request` → `200` no `cdni.meta`; a partir daí, o próximo `404` registrado é a próxima etapa.

Se o estágio 3 for o único bloqueio, ele fica **documentado como blocker** e tratado em etapa separada (decisão sobre confiança), sem misturar com DNS/protocolo/conteúdo.
